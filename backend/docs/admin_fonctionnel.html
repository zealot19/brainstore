00 Vue d'ensemble — Les 3 niveaux d'administration

L'administration de l'ERP est organisée en trois niveaux hiérarchiques distincts, chacun avec son périmètre de responsabilité et ses droits spécifiques.

NIVEAU 1 — SUPER ADMIN (Éditeur de la plateforme) Gère : Packages · Institutions · Paramètres globaux · Supervision de la plateforme
NIVEAU 2 — ADMIN INSTITUTION (Client ERP) Gère : Agences · Modules · Profils · Utilisateurs · Configuration de son tenant
NIVEAU 3 — ADMIN AGENCE (optionnel) Gère : Utilisateurs locaux · Configuration spécifique à l'agence

01 Gestion des Packages

Un package est l'offre commerciale souscrite par une institution. Il définit les modules accessibles, les limites d'usage et les conditions tarifaires.

1.1 Catalogue de packages

Chaque package est une offre commerciale avec les attributs suivants :

AttributDescription
NomStarter / Professional / Enterprise / Custom
Modules inclusListe des modules activables avec ce package
LimitesNombre max d'utilisateurs, d'agences, stockage fichiers (Go)
DuréeMensuel / Annuel / Perpétuel
PrixTarification par tranche d'utilisateurs
SupportNiveau de support inclus (email, téléphone, dédié)
StatutActif En test Archivé

1.2 Souscriptions

Chaque institution est liée à une souscription active qui évolue dans le temps :

Essai
→
Actif
⇄
Suspendu
→
Résilié
  • Package souscrit, date de début, date d'expiration
  • Nombre d'utilisateurs actifs vs limite du package
  • Alertes automatiques à J-30, J-7 et J-0 avant expiration
  • Upgrade / downgrade de package possible à tout moment
  • Historique complet de toutes les souscriptions

1.3 Gestion des limites

Dépassement de quota : Blocage automatique à l'atteinte du quota utilisateurs. Alerte à 80% du quota de stockage. Mode dégradé (lecture seule) en cas de suspension. Fenêtre de grâce configurable après expiration.

03 Gestion des Agences / Filiales

Institution (Siège) ├── Agence Nord │ ├── Sous-agence Ville A │ └── Sous-agence Ville B ├── Agence Sud └── Filiale XYZ ← entité légalement distincte

3.3 Comptabilité inter-agences

  • Chaque agence peut hériter du plan de comptes du siège ou avoir le sien
  • Consolidation financière disponible au niveau institution
  • Transactions inter-agences avec piste d'audit complète
  • Rapports disponibles par agence ou consolidés (toutes agences)

3.4 Accès par agence

Un utilisateur peut être assigné à une ou plusieurs agences. À la connexion, il choisit son agence active. Les données sont automatiquement filtrées selon cette agence. Certains profils (direction, audit) voient toutes les agences sans restriction.

06 Gestion des Profils (Rôles)

Un profil regroupe un ensemble cohérent de permissions correspondant à un rôle métier. Il est la brique centrale du contrôle d'accès.

6.1 Types de profils

TypeDescriptionModifiable
SystèmeSuper Admin, Admin Institution, Admin AgenceNon
Métier standardComptable, DRH, Caissier, Auditeur, Commercial…Partiellement
Métier personnaliséCréés et configurés librement par l'institutionOui

6.2 Héritage de profils

Profil: Manager RH ├── Hérite de: Employé RH (lecture + saisie de base) └── Permissions additionnelles: ├── Approbation des congés ├── Suppression de contrats └── Export des données RH
Un utilisateur peut avoir plusieurs profils simultanément. Les permissions sont l'union de tous ses profils, avec possibilité de retrait individuel sur certaines permissions.

6.3 Fonctionnalités de gestion

  • Clonage : Dupliquer un profil existant comme point de départ
  • Comparaison : Vue diff des permissions entre deux profils
  • Simulation : "Que voit cet utilisateur ?" — aperçu de l'interface selon profil
  • Audit : Historique des modifications apportées au profil
07 Gestion des Permissions

Les permissions s'organisent en 4 niveaux progressifs, du plus général au plus fin.

7.1 Niveau 1 — Permission de module

Accès ou non à l'ensemble d'un module. Si désactivé, aucune fonctionnalité du module n'est accessible.

7.2 Niveau 2 — Permission de modèle (CRUD)

Module HR · Modèle : Employee ┌─────────┬────────┬──────────┬───────────┬─────────┬────────┐ │ Profil │ Créer │ Lire │ Modifier │Supprimer│Exporter│ ├─────────┼────────┼──────────┼───────────┼─────────┼────────┤ │ DRH │ ✅ │ ✅ │ ✅ │ ✅ │ ✅ │ │ RH Mgr │ ✅ │ ✅ │ ✅ │ ❌ │ ✅ │ │ RH Asst │ ✅ │ ✅ │ ❌ │ ❌ │ ❌ │ │ Auditeur│ ❌ │ ✅ │ ❌ │ ❌ │ ✅ │ └─────────┴────────┴──────────┴───────────┴─────────┴────────┘

Actions disponibles : Créer · Lire · Modifier · Supprimer · Exporter · Importer · Approuver · Imprimer

7.3 Niveau 3 — Permission de champ

Modèle : Employee · Champ : "salaire_base" ┌──────────────────┬──────────┬────────────┐ │ Profil │ Visible │Modifiable │ ├──────────────────┼──────────┼────────────┤ │ Comptable junior │ ❌ │ ❌ │ ← champ masqué │ RH Manager │ ✅ │ ❌ │ ← lecture seule │ DRH │ ✅ │ ✅ │ ← accès total └──────────────────┴──────────┴────────────┘

7.4 Niveau 4 — Règles d'enregistrement (Record Rules)

Profil : Manager Agence Nord Règle : Voir uniquement les employés de son agence Filtre : employee.agence_id = current_user.agence_active_id Profil : Responsable Commercial Règle : Voir uniquement les clients qu'il a créés Filtre : client.created_by_id = current_user.id
Sécurité multi-tenant : Une règle d'enregistrement système s'applique en premier sur tous les querysets pour garantir qu'un utilisateur ne peut jamais accéder aux données d'une autre institution, quelles que soient ses permissions.

9.4 Tokens JWT

POST /api/v1/auth/login/ → access_token (TTL : 15 minutes) → refresh_token (TTL : 7 jours, rotation à chaque usage) POST /api/v1/auth/refresh/ ← renouvelle l'access token POST /api/v1/auth/logout/ ← blacklist du refresh token courant POST /api/v1/auth/logout-all/ ← invalide TOUTES les sessions actives Contenu du token : { "user_id": "uuid", "institution_id": "uuid", "agence_active_id": "uuid", "profils": ["DRH", "Admin Agence"], "exp": 1750000000 }
Révocation immédiate : Tout changement de profil, suspension ou changement de mot de passe invalide immédiatement tous les tokens actifs de l'utilisateur concerné.
