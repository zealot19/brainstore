1. Vision du projet

DreamsPOS ERP est un système de gestion intégré (ERP) multi-tenant développé avec Django REST Framework et Angular. La première verticale implémentée est le secteur Transport & Logistique (modèle Blue Bird Express / Brainstore ERP).

Verticale Transport (v2.0)
  • ✅ Gestion de flotte (véhicules, conducteurs, maintenance)
  • ✅ Configuration transport (villes, terminaux, routes, tarifs)
  • ✅ Gestion des voyages (départs, embarquement, équipage)
  • ✅ Billetterie (réservations, billets QR, bagages)
  • ✅ Colis (tracking REGISTERED→DELIVERED, paiement COD)
  • ✅ Trésorerie (caisses, banques, sessions, virements)
  • ✅ Réservation en ligne (API publique + Campay MoMo)
Fondation ERP (v1.0)
  • ✅ Authentification JWT + 2FA TOTP
  • ✅ Multi-tenant (Company + Agencies)
  • ✅ RBAC (Rôles, Profils, Permissions)
  • ✅ Ressources Humaines
  • 🔧 Finance OHADA, Inventaire, POS, CRM

3. Architecture backend

Pattern Services / Selectors

Request HTTP
→
URLs
→
Views (thin)
→
Serializers
→
Services / Selectors
→
Models → DB
Selectors (lectures)

QuerySets, filtres, annotations, agrégations. Aucune écriture en base.

Services (écritures)

Logique métier, @transaction.atomic, select_for_update() pour les soldes. Lève ApplicationError.

Multi-tenancy — Shared Schema

Tous les modèles métier portent un champ company_id (FK → system_config.Company). Les données d'une société ne sont jamais visibles par une autre.

Pattern company=None pour les données partagées (ex: VehicleCategory, FareClass, MaintenanceType) — accessibles à toutes les sociétés via Q(company_id=X) | Q(company__isnull=True).

BaseModel

  • UUID pk (non devinable)
  • created_at / updated_at auto
  • Soft delete : is_deleted, deleted_at, soft_delete(user)
  • Audit : created_by, updated_by, deleted_by
  • OdometerLog et ParcelEvent héritent de models.Model (logs immuables — pas de soft-delete)

HasPermission — factory DRF pour SCIG

Fichier : apps/admin_rbac/permissions.py

from apps.admin_rbac.permissions import HasPermission

# Endpoint sécurisé par code de permission granulaire
class ValidateZoneView(APIView):
    permission_classes = [IsScigSageEnabled, HasPermission("scig.zone.validate")]

# Vue mixte GET/POST avec permissions différentes par méthode
class InventorySessionListView(APIView):
    permission_classes = [IsScigSageEnabled]
    def get_permissions(self):
        if self.request.method == "POST":
            return [IsScigSageEnabled(), HasPermission("scig.session.create")()]
        return [IsScigSageEnabled(), HasPermission("scig.session.view")()]

La factory retourne une classe (pas une instance) — compatible avec permission_classes DRF. Délègue à get_user_permissions(user, company_id) du selector existant. Superuser reçoit {"*"} = toutes les permissions.

Push Sage 100
SUBMITTED → ORANGE (RECHECK) → réouverture → IN_PROGRESS IN_PROGRESS bloquée → force-unlock (/unlock/) → NOT_STARTED

Zone ouverte par le terminal (lock device_id) → scan articles → soumission → validation manager → push F_ARTSTOCK.
Submit bloqué tant que toutes les zones ne sont pas VALIDATED.
RECHECK : manager renvoie la zone en Orange (avec note motif) → opérateur clique "Réouvrir pour correction" → retour IN_PROGRESS, données conservées.
Force-unlock : si le terminal Zebra plante en cours de comptage, le manager déverrouille via POST /unlock/ → zone repart à NOT_STARTED, toutes les InventoryLine (qty_counted) sont préservées.

  • Snapshot stock théorique à l'ouverture de zone — comparaison physique vs Sage
  • Transfert : vérification stock disponible avant ajout de ligne (évite sur-planification)
  • Push Sage : update atomique F_ARTSTOCK.AS_StockReel avec rollback pyodbc

22. Conventions de développement

Règles absolues

  1. Jamais auth.User dans les ForeignKey. Toujours settings.AUTH_USER_MODEL ou "authentication.User".
  2. Jamais d'ORM dans les views. Selectors pour les lectures, services pour les écritures.
  3. Tous les modèles métier héritent de BaseModel (UUID, timestamps, soft-delete, audit). Exception : logs immuables (OdometerLog, ParcelEvent) → models.Model.
  4. Services Write : paramètres explicites. Pas de **kwargs → objects.create() — risque de conflits FK résolues.
  5. FK optionnelles dans les WriteSerializers : required=False, allow_null=True, default=None.
  6. select_for_update() pour toute mise à jour de solde (CashRegister.current_balance, BankAccount.current_balance) → prévient les race conditions.
  7. Références croisées entre modules : utiliser les strings FK ("fleet.Vehicle", "voyage.Trip") pour éviter les circular imports.

Pattern company=None (données globales partagées)

Certains modèles de référence sont partagés entre toutes les sociétés : VehicleCategory, FareClass, MaintenanceType.

# Dans les selectors — récupérer données system + company
qs = VehicleCategory.objects.filter(
    Q(company_id=company_id) | Q(company__isnull=True),
    is_deleted=False
)
